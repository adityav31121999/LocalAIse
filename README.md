# LocalAIse

**Private, local-first AI workspace for folders you own.**

LocalAIse is a desktop app that turns any folder into a project you can chat with. Documents are
indexed on your machine, answers are generated by a local `llama-server`, and every citation points
back to the file it came from. There is no account, no telemetry, and no cloud dependency: open the
project folder in Explorer or Finder and you see exactly what the app wrote.

`v0.1` · Windows & Linux · MIT · React + Tauri 2 + llama.cpp

---

## Features

### Projects are plain folders
- Point LocalAIse at any directory and it becomes a project with its own sources, chats, diary,
  outputs and settings.
- Everything lives in ordinary files (`project.json`, `chats/*.json`, `diary/*.md`,
  `outputs/`) — readable, editable, and portable outside the app.
- Deleting the hidden `.LocalAIse/` folder resets the app's view without touching your files.

### Grounded chat
- Answers are grounded in the project's indexed sources and carry citations (file + excerpt).
- Multiple saved conversations per project, each stored as its own JSON file; the picker shows
  `Chat 1`, `Chat 2`, …
- Attach text files or PDFs to a single message; set a per-project system prompt; adjust sampling
  (temperature, top-p, top-k); toggle the model's thinking trace.
- **Agent mode** and **internet access** are explicit per-project switches. Internet starts **off**.

### Document viewer
- Renders PDFs visually, extracts text from PDF, DOCX, Markdown, TXT, CSV, XLSX and more.
- One-click summarize, **Key figures & tables** extraction, and **Cite in Chat** — the passage is
  quoted into the composer.
- If summarization fails, the viewer offers a map-reduce fallback or a raw excerpt instead of a
  dead end.
- Save summaries as Markdown next to the source.

### Analysis and research
- **Analysis** workbench: summarize, extract tables, flag inconsistencies, or compare two documents,
  with output history and Markdown / JSON / print exports.
- **Research** workbench: generate a multi-step plan, edit the checklist, approve it, and get a
  synthesized, cited report.
- Web-backed deep research runs only when a project's internet toggle is on; requests pass through a
  gate that blocks private ranges and logs every attempt.

### Journal
- A calendar plus recent-entry list beside a distraction-free editor, with a centered/full-width
  switch and word/character/reading-time metadata.
- Per-project diaries are opt-in; the personal diary lives in a folder you choose during onboarding.

### Models and hardware
- First-run onboarding checks the machine, helps pick a model, and sets up a personal folder.
- Model hub downloads GGUF models from a curated catalog with progress events.
- Tune context length, KV-cache quantization, GPU layers, batching, threads, mmap and MoE
  placement — with a live memory bar showing weights, KV cache, overhead and free VRAM/RAM before
  the server starts.
- CPU-only by default. GPU backends (CUDA / Vulkan) are an explicit, checksum-verified,
  user-initiated install from the hardware settings; the installer bundles no GPU runtimes.

### Appearance and auditability
- Multiple themes (including a neutral deep-slate dark mode), light/dark/system modes, and
  comfortable/compact/spacious density.
- Every file, network and tool action is written to `.LocalAIse/activity.log` (JSONL) and shown in
  the project's Activity tab.
- No telemetry.

## Stack

| Layer | Technology |
|---|---|
| UI | React 19, TypeScript, Zustand, Vite 5, lucide-react, pdf.js |
| Desktop shell | Tauri 2 (Rust 2021) |
| Inference | `llama-server` from llama.cpp, supervised as a child process |
| Retrieval | Rust ingest + chunking + scoring, optional local embeddings (`fastembed`) |
| Research storage | SQLite (`rusqlite`) + `sqlite-vec` for evidence during deep research |
| Web extraction | `reqwest` + `dom_smoothie` + `htmd`, `chromiumoxide` for JS-rendered pages |
| Packaging | NSIS (Windows), AppImage / DEB (Linux) |

## Architecture

```
React UI (src/)            state, rendering, keyboard — no filesystem access
      │  Tauri IPC
Rust commands              thin #[tauri::command] entry points
      │
Domain modules             runtime supervisor, projects, ingest, retrieval,
                           agent loop, personal space, research, activity log
      │
llama-server               child process on 127.0.0.1 with a per-session token
per-project files          project folder + .LocalAIse/ app state
```

A few rules keep the layers honest:

- The UI never touches the filesystem; every read/write crosses a validated Tauri command.
- Outbound HTTP exists only in `network/` (gated per project) and `models/download.rs`
  (user-initiated downloads). Both audit to the activity log.
- The sandbox (`sandbox/`) is defined once and used by every tool, so path traversal and symlink
  escapes are rejected in one place.
- `runtime/args.rs` is the only place `llama-server` flags are spelled out; the API key travels via
  the environment, never argv.

Details: [`docs/architecture.md`](docs/architecture.md).

## Requirements

- **Node.js 20+** and npm
- **Rust 1.77+** with Cargo
- **Tauri 2 system prerequisites** for your platform:
  - Windows: WebView2 (preinstalled on Windows 11) and MSVC build tools
  - Linux: `webkit2gtk-4.1`, `libappindicator`, `librsvg`, `patchelf` and build essentials
  - See the [Tauri prerequisites guide](https://v2.tauri.app/start/prerequisites/)
- Optional: a Vulkan or CUDA toolchain only if you build a GPU backend locally. The in-app GPU
  installer needs nothing beyond the app itself.

Windows and Linux are the packaged targets today (`nsis`, `appimage`, `deb`) and the only platforms
with llama-server runtime folders.

## Getting started

```bash
git clone https://github.com/<you>/LocalAIse.git
cd LocalAIse
npm install
```

### 1. Provide the llama-server runtime

The binaries are gitignored and built from a pinned llama.cpp checkout:

```bash
git clone --depth 1 --branch b11678 https://github.com/ggml-org/llama.cpp vendor/llama.cpp
npm run fetch-llama-server
```

> Keep the branch in sync with `PINNED_TAG` in `scripts/fetch-llama-server.ts`. If
> `vendor/llama.cpp` is missing, the script prints the exact clone command for the pinned tag.

This produces a CPU-only build in `resources/llama/<platform>/`. GPU builds are optional and can be
installed later from **Settings → Model & Runtime → Hardware**, or built with:

```bash
npm run fetch-llama-server -- windows-x64 cuda
npm run fetch-llama-server -- linux-x64 vulkan
```

### 2. Run the desktop app

```bash
npm start
```

`npm start` runs `tauri dev`, which starts Vite on port 1420 and launches the Rust shell. On first
launch, onboarding walks through hardware detection, model selection/download, and choosing a
personal notes folder.

### 3. Or run just the UI

```bash
npm run dev
```

Opens `http://localhost:1420` with mock data. This is useful for layout work: in a plain browser the
app cannot reach the filesystem or the model, so API calls are simulated (`isTauri === false`).
Onboarding is gated by `localStorage["LocalAIse.settings"].onboardingComplete` if you need to skip it.

## Using the app

- **Rail (global):** Home / projects, Model Hub, Settings, Hardware.
- **Top bar (project):** `Workspace` (chat + sources + viewer), `Files`, `Analysis`, `Research`,
  `Journal`, `Activity`. The breadcrumb pill opens the project menu (copy path, toggle diary).
- **Chat:** pick or start a conversation, attach files, set a system prompt, and send. Clicking a
  citation opens the source; document actions can cite passages back into the composer.
- **Model Hub / Settings:** download models, choose the active model, tune inference, install a GPU
  backend, switch themes and density.
- **Internet:** off by default per project. Turning it on is required for web-backed research and
  agent tools, and does not bypass the SSRF/scheme policy.

## Building installers

```bash
# Frontend typecheck + production bundle
npm run build

# Optional: confirm no GPU libraries leaked into the frontend bundle
npm run check-bundle

# Stage only the CPU llama-server files for packaging
npx tsx scripts/stage-bundle.ts

# Build desktop installers (NSIS / AppImage / DEB)
npm run tauri build
```

Artifacts land in `src-tauri/target/release/bundle/`. Verify the runtime binaries against the
recorded SHA-256 ledger at any time:

```bash
npm run verify-binaries
```

## Project folder format

```
MyProject/
├── project.json        # manifest: layout, diary switch, RAG scope
├── data/               # your source files (the knowledge base)
├── chats/              # chat-001.json, chat-002.json, …
├── diary/              # optional: one Markdown page per date
├── outputs/            # files the assistant produces
├── <your folders>/     # anything else, tracked in project.json
└── .LocalAIse/         # app state — safe to delete to re-index
    ├── index.json
    └── activity.log
```

`data/`, `chats/`, `diary/`, `outputs/` and `.LocalAIse/` are reserved. RAG indexes everything
outside them unless `ragPaths` in `project.json` narrows the scope.

Full details: [`docs/project-format.md`](docs/project-format.md).

## Privacy and security

- Files never leave the machine. Projects and the personal space are plain folders.
- Internet is off per project and every request passes one gate; private ranges and non-HTTP schemes
  are always refused.
- The webview gets no general network access — the CSP allows only `self` and the IPC bridge.
- llama-server binds to `127.0.0.1` on a random port with a random per-session token.
- CPU runs pin every GPU backend off, including on a GPU-capable install.
- Agent writes land in `outputs/`; overwrites and deletions require confirmation.
- Model downloads and GPU archives are checksum-pinned; release bundles are scanned for GPU
  libraries.
- No telemetry. Ever.

Full threat table: [`docs/security-model.md`](docs/security-model.md).

## Troubleshooting

**`Port 1420 is already in use`**

A previous Vite process is still running. Stop it, then retry:

```powershell
# Windows
Get-NetTCPConnection -LocalPort 1420 -State Listen |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

```bash
# Linux / macOS
lsof -ti tcp:1420 | xargs -r kill
```

**The model never becomes ready**

- Confirm `resources/llama/<platform>/llama-server` exists; if not, re-run
  `npm run fetch-llama-server`.
- Run `npm run verify-binaries` to catch a corrupted or stray runtime file.
- Check the terminal that runs `npm start`; llama-server stderr is logged there.
- Context length or GPU layers may exceed available memory — lower them in the model settings, where
  the memory bar shows what fits.

**GPU is not used**

CPU-only is the default. Install a GPU backend from **Settings → Model & Runtime → Hardware** and
select a GPU device in the inference settings. In CPU mode LocalAIse deliberately passes
`--device none` and empties the backend device lists.

**I see demo data and nothing is saved**

You are running `npm run dev` in a browser. Use `npm start` for the desktop app with real files and
inference.

**Reset onboarding / app state**

- Onboarding: clear `localStorage["LocalAIse.settings"]` for `localhost:1420` (dev) or the app origin.
- Per project: delete the project's `.LocalAIse/` folder and reopen the project to re-index.
- Globally: remove the app-data folder for `dev.LocalAIse.desktop`, then relaunch. User project
  folders are never touched by this.
